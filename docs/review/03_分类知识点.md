# Webserv 复习笔记（三）：分类知识点

范围：当前 C++ 服务端、配置、CGI 示例、Python/Shell 测试和 Makefile 中直接涉及的知识，以及理解它们必需的基础。编号采用“类别.条目”，便于逐项复习。它不是所有计算机知识的百科，也不是学校允许函数清单；具体限制仍以提交版本 subject 为准。

## 1. C++98 基础与对象设计

| 编号 | 知识点 | 简洁解释与代码联系 |
| --- | --- | --- |
| 1.01 | class 与 struct | 默认访问权限分别是 private 和 public。项目用 class 封装行为，用 RequestState、MultipartPart 聚合数据；两者都可以有成员函数。 |
| 1.02 | public / private | public 是外部接口，private 是内部细节。Server 只公开构造、析构和 run，事件处理函数留在 private。 |
| 1.03 | 构造函数 | 创建对象时建立初始状态。CgiHandler 把 fd、pid 初始化为 -1，避免把未取得的资源当作有效资源。 |
| 1.04 | 初始化列表 | 在进入构造函数体前初始化成员；引用成员必须初始化，不能事后重新绑定。RequestHandler::_server 使用初始化列表。 |
| 1.05 | 析构函数 | 对象寿命结束时执行。局部对象会自动析构，new 出来的对象需 delete；空 Client 析构不会自动 close 它保存的整数 fd。 |
| 1.06 | 拷贝构造 | 用已有对象创建新对象。ServerConfig、Client 等按值进入容器时可能触发；复制 fd 数字不等于复制连接。 |
| 1.07 | 赋值运算符 | 改写已经存在的对象；operator= 常用 if (this != &other) 防自赋值并返回 *this。RequestState.reset 会给 request 赋值。 |
| 1.08 | 禁止拷贝 | C++98 可把拷贝构造/赋值声明为 private 且不定义。Server、CgiHandler 等使用此方式，防止资源被两个对象错误共享。 |
| 1.09 | 隐式特殊成员 | 未手写不等于不存在。MultipartPart、TokenStream 等仍可能使用编译器生成的构造/复制/析构；完整索引只计显式定义。 |
| 1.10 | 值、引用、指针 | 值产生独立副本；引用表示已有对象的别名；指针可为空。LocationConfig* 为空表示无匹配 location。 |
| 1.11 | const 引用 | 只读借用大型对象，避免复制。getBody 返回 const string&；使用方不能让引用比源对象活得更久。 |
| 1.12 | const 成员函数 | 承诺不通过 this 修改普通成员。Client 的 getRequestState 有 const 和非 const 重载，返回权限不同。 |
| 1.13 | 指针引用 | const LocationConfig *&location 表示“引用一个指向只读配置的指针”；parseClientRequest 可以让调用方的指针指向匹配配置。 |
| 1.14 | friend | HttpRequest 声明 RequestParser 为友元，让解析器写入私有字段；其他使用者通过 getter 读取。 |
| 1.15 | static 成员函数 | Utils::trim 可直接通过类名调用，不依赖对象，也没有 this。函数里的 static const hex 数组有静态存储期。 |
| 1.16 | 作用域解析符 :: | Server::run 表示 Server 类的 run；std::string 属于标准命名空间。项目不需要自定义 namespace 才能使用这些语法。 |
| 1.17 | 前向声明 | class CgiHandler; 足以声明指针/引用，但访问成员、按值保存对象、部分模板实例化需要完整定义。ConfigParser.hpp 使用的 ListenConfig/LocationConfig 目前依赖先前 include，不能把偶然 include 顺序当成好习惯。 |
| 1.18 | 头文件保护 | #ifndef / #define / #endif 防重复展开。声明放 .hpp、实现放 .cpp 有利于分离接口与实现。 |
| 1.19 | enum | 用具名整数表示状态，例如 STAGE_HEADERS；避免用难懂的 0、1、2，但 enum 本身不执行状态转换。 |
| 1.20 | static_cast | 明确数值/枚举转换；bytes 为正后转 size_t。负数直接转无符号会变成大数。 |
| 1.21 | reinterpret_cast | socket API 需要通用 sockaddr*，代码把 sockaddr_in* 转换为该指针类型；它不是在验证内存布局。 |
| 1.22 | const_cast | execve 的 argv 接口使用 char*，代码转换 c_str 指针的类型；不能据此修改原本不可写的内存。 |
| 1.23 | size_t 与 ssize_t | size_t 表示非负大小；ssize_t 能表示字节数及 -1 错误。pid_t 表示进程 ID，time_t 表示时间，socklen_t 表示地址长度。 |
| 1.24 | sizeof 与 NULL | sizeof 给出对象/类型占用字节数；NULL 是 C++98 常见空指针写法，不能用它判定所有 fd 无效，fd 的常见无效值是 -1。 |
| 1.25 | 短路求值 | && 左边为 false 时不算右边，保护下标访问，例如先检查 value.size() 再访问 value[3]。 |
| 1.26 | 位运算 | flags 与 O_NONBLOCK 按位或来添加标志，revents & POLLIN 检查标志；移位与 0xFF 用于取 IPv4 的每个字节。 |
| 1.27 | bool 返回值语义 | false 不总等于错误：writeBody 的 false 表示尚未完成；preCheck 的 true 表示已生成响应。读函数前先确定返回值契约。 |

## 2. 标准库、字符串和容器

| 编号 | 知识点 / API | 简洁解释与代码联系 |
| --- | --- | --- |
| 2.01 | std::string | 带长度的字节序列，可包含 NUL。HTTP 正文长度使用 size()，不能用遇到 NUL 就结束的 C 字符串长度概念。 |
| 2.02 | size / empty / clear | 分别查询长度、是否为空、清空内容；clear 不保证释放 capacity。 |
| 2.03 | find / rfind / find_last_of | 查子串或字符的位置；npos 表示未找到。substr(npos) 会出问题，所以先判断。 |
| 2.04 | find_first_not_of / find_last_not_of | 找两端第一个非指定字符，Utils::trim 用它们去掉空白。 |
| 2.05 | substr / compare | substr 创建子串副本；compare 比较指定区间。频繁对大 body 做 substr 会增加内存和复制。 |
| 2.06 | append / assign / += | append 追加，assign 替换；带长度或偏移的版本适合二进制正文，避免错误依赖字符串结束符。 |
| 2.07 | erase / insert | 修改字符串局部；buildCgiResponse 删除 CGI 头并在开头插入 HTTP 头，可能移动正文或重新分配。 |
| 2.08 | c_str / data | 为 C API 提供字符存储指针；c_str 以 NUL 结尾。C++98 的 data 不应假定有结束 NUL，write(data, size) 因为给了长度而合适。 |
| 2.09 | string::swap | 交换存储而非逐字节复制。与局部空字符串交换后，旧缓冲随局部对象析构释放。 |
| 2.10 | std::vector | 连续元素容器，push_back 添加，erase 删除。扩容可能使引用/指针失效；删除会使后面的元素移动。 |
| 2.11 | std::map | 按 key 查 value，例如 fd→Client、扩展名→解释器。find 不插入；operator[] 在 key 不存在时会插入默认 value。 |
| 2.12 | map::insert / make_pair | 以键值对插入；_clients 用 insert(make_pair(fd, Client(...)))，因为 Client 禁止外部默认构造。 |
| 2.13 | std::set | 唯一元素集合。seen.insert(token).second 为 false 表示已存在，用来拒绝重复配置指令。 |
| 2.14 | iterator / const_iterator | 容器遍历位置；const_iterator 不允许通过它改元素。begin / end 构成半开区间，end 不能解引用。 |
| 2.15 | erase 与迭代 | 删除 vector 元素后当前下标指向后继元素；马上 ++i 可能跳过。Server 的清理循环有意使用 continue。 |
| 2.16 | stringstream / ostringstream | 内存中的输入输出流，>> 解析 token，<< 构建文本，str() 取得字符串。C++98 没有 std::to_string，项目用流转换。 |
| 2.17 | std::hex | 流操纵符，让数字以十六进制解析；用于 URI %HH。不是普通字符串函数。 |
| 2.18 | strtol | 把 C 字符串转换为 long；endPtr 指向未转换部分。先检查值范围，再转 int；前导符号等接受范围与手写纯数字解析不同。 |
| 2.19 | numeric_limits<T>::max | 获取类型最大值。十进制累计前检查 result > (max-digit)/10；chunk 十六进制对应除 16。 |
| 2.20 | isdigit / isxdigit / tolower / isspace | 字符分类与大小写转换；通常应先转 unsigned char，避免负 char 参数。Tokenizer 当前直接 isspace(c)，应作为阅读边界记住。 |
| 2.21 | ifstream / ofstream | 文件输入/输出流；离开作用域自动析构关闭，但要显式知道 close 是否失败，就要手动 close 后检查流状态。 |
| 2.22 | is_open / write / close / rdbuf | 分别检查打开状态、按字节写、关闭、获取底层流缓冲。buffer << file.rdbuf() 会将文件内容读到内存。 |
| 2.23 | 流错误状态 | if (!file) 检查失败状态，不是检查对象是否存在。close 后正常关闭的流不一定失败；关闭过程中出错才可能设置错误位。 |
| 2.24 | cout / cerr / endl | 标准输出、标准错误、换行并刷新。频繁 endl 和调试输出可能影响压力测试性能。 |
| 2.25 | memset / strcpy | 分别按字节初始化内存、复制 NUL 结尾字符串。creatEnvp 分配 size+1，再 strcpy，留出结束 NUL。 |

## 3. 配置文件与解析设计

| 编号 | 知识点 | 简洁解释与代码联系 |
| --- | --- | --- |
| 3.01 | 词法分析 | Tokenizer 把文本转成 token，如 server、{、root、./www、;、}。当前不是支持引号、转义等全部语法的通用配置语言。 |
| 3.02 | 语法分析 | ConfigParser 按 token 顺序构造对象；缺分号、缺花括号、未知指令都应拒绝。 |
| 3.03 | token 流 | peek 看但不推进；consume 取并推进；match 匹配成功才推进；expect 必须成功，否则 throw。 |
| 3.04 | 语义验证 | ConfigValidator 检查合法语法组合是否有意义，例如相同 location 路径、重复方法、上传缺 POST。 |
| 3.05 | 默认值 | ServerConfig 默认 root=./www、index=index.html、body 上限 1 MiB，error_pages 初始为空；ListenConfig 默认 0.0.0.0:8080，但 server 未写 listen 仍被验证拒绝。 |
| 3.06 | 覆盖与继承 | location 的 root/index 缺省时复制 server 值；body 上限运行时选取，location 显式设置则覆盖，server 不是额外硬上限。 |
| 3.07 | 显式设置标记 | clientMaxBodySizeSet 区分未配置与配置为 0；0 表示无限制，不是禁止正文。 |
| 3.08 | 重复键策略 | root 等同一块只许一次；error_page 按状态码去重；cgi 按扩展名去重；不同块或不同扩展名可独立配置。 |
| 3.09 | 验证层次不相同 | parseErrorPage 先接受 100～599，Validator 再要求 400～599；实际最终接受的是两个阶段共同允许的范围。 |
| 3.10 | 相对路径基准 | 服务端配置相对于启动目录；CGI 执行前 chdir，解释器相对路径相对于脚本目录。../cgi_tester 因此与项目根目录下的 ./cgi_tester 不是同一书写基准。 |

## 4. TCP、socket 与地址

| 编号 | 知识点 | 简洁解释与代码联系 |
| --- | --- | --- |
| 4.01 | TCP 字节流 | TCP 提供有序字节传输，没有 HTTP 请求边界；一次写可能多次读，多次写也可能一次读到。 |
| 4.02 | IP 与端口 | IP 选择地址/接口，端口区分服务端点；当前 AF_INET 使用 IPv4，SOCK_STREAM 使用流式 socket。 |
| 4.03 | 监听 fd 与客户端 fd | listen socket 负责等连接；accept 返回新的连接 socket，后续 recv/send 用新 fd。 |
| 4.04 | 0.0.0.0 与 loopback | 0.0.0.0 监听所有本地 IPv4 接口；127.0.0.1 是本机环回。容器里的环回地址属于容器自身网络空间。 |
| 4.05 | SO_REUSEADDR | 调整 bind 的地址复用规则，常用于服务重启；不等于允许任意两个活动服务器无条件抢占同一地址，也不实现虚拟主机。 |
| 4.06 | backlog | listen 的排队参数，项目使用 SOMAXCONN；不等于最大总客户端数或 worker 数量。 |
| 4.07 | 字节序 | 网络数字通常采用网络字节序；ntohl 把 IPv4 整数转为主机顺序，再移位格式化四段地址。 |
| 4.08 | 地址解析 | getaddrinfo 生成可交给 bind 的 sockaddr 结果；hints 指定 IPv4/TCP，freeaddrinfo 释放返回列表。 |
| 4.09 | getsockname | 查询 socket 本地地址；当前代码对 listenFd 查询，若监听通配地址，SERVER_NAME 可能得到 0.0.0.0，而不是请求 Host。 |
| 4.10 | 虚拟主机 | 多个域名共用同一监听端点时，需要按 Host 选择配置；当前配置选择在 accept 阶段已由 listenFd 决定。 |

## 5. 非阻塞 I/O、poll 与事件循环

| 编号 | 知识点 | 简洁解释与代码联系 |
| --- | --- | --- |
| 5.01 | 文件描述符 fd | 进程内索引，能代表 socket、pipe、文件。fd=11 在不同进程或不同时刻不一定代表同一资源。 |
| 5.02 | O_NONBLOCK | 设置后，不能立即完成的 I/O 不会按普通阻塞模式等待；它不意味着成功，也不意味着会传完所有字节。 |
| 5.03 | fcntl | F_GETFL 取得状态标志；F_SETFL 写回原 flags 与 O_NONBLOCK 按位或的结果，以保留其他标志。学校对平台/调用方式的限制需单独核对。 |
| 5.04 | I/O 多路复用 | 一个 poll 同时等多个 fd，再处理就绪对象。一个线程也能交替推进很多连接，不需要一连接一线程。 |
| 5.05 | pollfd | fd 是对象，events 是订阅，revents 是本次结果；events=0 仍可能报告错误/挂断。 |
| 5.06 | POLLIN / POLLOUT | 分别表示可以尝试读/写；不保证应用层消息完整，也不保证任意大的操作一次完成。 |
| 5.07 | POLLHUP | 对端关闭管道时可能仍有残留数据；CGI 输出端不能看到 HUP 就直接丢掉未读内容。 |
| 5.08 | POLLERR / POLLNVAL | 分别表示错误条件、无效 fd；不应该继续当正常可读写对象处理。 |
| 5.09 | poll 返回值 | 正数是 revents 非零的元素数量，0 是等待超时，-1 是错误；不是字节数，也不是单独某个 fd。 |
| 5.10 | 部分读取 / 写入 | recv/read/send/write 返回正数表示本次字节数。Client._bytesSent、CgiHandler._bodyOffset 保存下一次起点。 |
| 5.11 | EOF | 对非零长度 read/recv 请求，返回 0 通常表示流结束；它不是 HTTP 的空正文，也不是“再等等”。 |
| 5.12 | 负值与 errno | 通用系统编程会区分临时不可用等原因；本项目按课程约束，不在 read/write 后依据 errno 调整行为，负值走当前失败策略。不能推广为所有网络程序的通用做法。 |
| 5.13 | 调度公平性 | 当前就绪回调通常只做一次 I/O，之后回到循环，避免单个连接连续占用；但大字符串处理仍会拖慢其他连接。 |
| 5.14 | 忙循环 | 若永久订阅 POLLOUT，空闲 socket 常持续可写，poll 不断返回；应在确有待发响应时才订阅。 |
| 5.15 | 用户态登记与内核资源 | vector/map erase 只改登记；close 释放内核 fd。两者都要处理，且不要 double-close 已复用的新 fd。 |
| 5.16 | 普通文件的限制 | poll 并不能使常规磁盘访问变成异步磁盘 I/O；当前 ifstream/ofstream 操作仍在主线程中执行。 |

关于 events/revents、挂断残留数据与 poll 返回值，可对照 [Linux poll 手册](https://man7.org/linux/man-pages/man2/poll.2.html)。

## 6. HTTP 报文与状态机

| 编号 | 知识点 | 简洁解释与代码联系 |
| --- | --- | --- |
| 6.01 | 请求行 | method SP target SP version CRLF，例如 GET /images/a.png?x=1 HTTP/1.1。项目用流抽取字段并拒绝额外字段。 |
| 6.02 | path / query | ? 前为路径，后为查询；先拆分再解码，避免 %3F 被误当原始分隔符。 |
| 6.03 | CRLF 与头体分隔 | HTTP 行通常以 \r\n 结束，空行分隔 header 和 body；CGI 输出额外兼容 \n\n。 |
| 6.04 | header 名称 | 大小写不敏感，项目存为小写。名称仅接受字母数字与指定 token 符号，不能把空格或 / 当合法名称字符。 |
| 6.05 | header 值 | 项目拒绝 NUL、裸 CR/LF、DEL 等控制字符，允许横向 Tab；先检查再 trim。 |
| 6.06 | Host | HTTP/1.1 请求需有 Host；当前检查存在、非空和不可重复，但不据此选虚拟主机，也未完整解析其语法。 |
| 6.07 | Content-Length | 正文的字节数，不包括头；不是字符串字符数，更不是整个 TCP 数据包大小。 |
| 6.08 | chunked | 每块由十六进制大小行、数据、CRLF 构成；0 块终止。项目把 chunk 数据合并后交给 handler/CGI。 |
| 6.09 | chunk 简化 | 当前只接受纯十六进制大小和直接结束空行，未实现扩展参数和 trailer。 |
| 6.10 | 长度歧义 | 同时出现 Content-Length 与 Transfer-Encoding 容易导致不同组件理解不同消息边界，当前直接 400。 |
| 6.11 | 增量解析 | 输入不足时保留状态，下次继续；并不要求每次收到数据从头解析，也不自动意味着内存可恒定。 |
| 6.12 | 三种结果 | OK 是阶段成功；INCOMPLETE 表示等数据；ERROR 才是拒绝。PARSE_COMPLETE 表示整个请求完成。 |
| 6.13 | 请求上限 | 请求行 8192、headers 32768、chunk 大小行 1024 字节；body 限制由配置决定。限制的是不同部分，不应混成一个数。 |
| 6.14 | keep-alive | 一条 TCP 连接顺序处理多个请求。当前 HTTP/1.1 默认开启，Connection 值恰为 close 时关闭，未完整解析逗号分隔 token 列表。 |
| 6.15 | pipelining | 客户端在前一响应结束前发送后续请求；服务器保留多余 readBuffer 并按顺序响应，当前不并行处理同一连接的请求。 |
| 6.16 | 响应序列化 | 状态行 + 响应头 + 空行 + 正文。HttpResponse 保存结构化结果，getResponse 才转成可发送字节。 |
| 6.17 | MIME 类型 | Content-Type 告诉客户端如何理解正文；getMimeType 根据扩展名映射，不识别则 application/octet-stream。 |
| 6.18 | 405 与 501 | 405 表示当前资源不允许该方法，带 Allow；501 表示普通分发没有实现该方法。preCheck 在前，所以 HEAD 在只允许 GET 的 location 先得到 405。 |
| 6.19 | 403 / 404 / 500 | 分别表达拒绝访问、未找到、内部失败；当前不查 errno，stat 失败常统一 404，不是精细错误原因分类。 |
| 6.20 | 413 / 414 / 431 / 505 | 正文太大、请求目标/请求行限制、header 太大、版本不支持；本文按项目实际返回路径解释。 |
| 6.21 | 200 与 201 | 普通操作成功通常 200，新建资源 201；当前上传按文件是否原先存在判断。 |
| 6.22 | 重定向 | 301/302/303/307/308 通过 Location 告诉客户端下一地址；307/308 的标准用途保留方法，但项目只是生成这些状态与 Location。 |

## 8. CGI、进程、管道与信号

| 编号 | 知识点 | 简洁解释与代码联系 |
| --- | --- | --- |
| 8.01 | CGI 全称与边界 | Common Gateway Interface，是 Web 服务器与外部程序交换请求/响应的约定；不是 Python 专属协议。 |
| 8.02 | fork | 创建子进程，父进程得到子 PID，子进程得到 0，失败为 -1；父子从同一调用之后走不同分支。 |
| 8.03 | 写时复制 | fork 后内存通常通过 copy-on-write 共享物理页，写入才可能复制；不能简单假定立刻完整复制或永远零成本。 |
| 8.04 | pipe | 返回读端 [0] 和写端 [1]，是一条单向字节通道；项目用两条管道完成请求输入和响应输出。 |
| 8.05 | 关闭多余管道端 | 父子进程都继承 fd；不关闭多余写端会让读端迟迟看不到 EOF，还可能延长其他连接寿命。 |
| 8.06 | dup2 | 让指定编号引用源 fd 对应的打开对象；stdin=0、stdout=1。复制后应关闭原始多余 fd。 |
| 8.07 | 阻塞 CGI 与非阻塞父进程 | 项目只将父进程使用的输入写端、输出读端设非阻塞；CGI 的 stdin/stdout 可以保持普通阻塞流接口。 |
| 8.08 | execve | 用新程序替换当前子进程映像，成功不返回；不会另外再创建一个 PID，也不会像 shell 那样替你解析整条命令。 |
| 8.09 | argv / envp | 都是以 NULL 结尾的字符指针数组；argv 放参数，envp 放 KEY=VALUE。creatEnvp 的拼写是源码现名。 |
| 8.10 | 环境变量 | 为 CGI 提供 method、query、body 长度和客户端信息；HTTP 头转换成 HTTP_XXX。环境是启动时快照，不是共享 map。 |
| 8.11 | chdir | 改当前进程工作目录；在子进程里调用不改变父进程工作目录。relative.py 因此能打开脚本旁边的 data.txt。 |
| 8.12 | shebang | #!/usr/bin/python3 指定解释器；#!/usr/bin/env python3 通过 env 和 PATH 查找。当前服务器显式 execve 解释器时，脚本 shebang 不负责选择解释器。 |
| 8.13 | execve 与 PATH | execve 使用传入路径，不自动搜索 PATH；相对路径受 chdir 影响。绝对解释器路径更易理解。 |
| 8.14 | stdin / stdout / stderr | CGI 从 stdin 读正文，stdout 写 CGI 头和正文；stderr 用于异常/日志，当前继承 webserv 的错误输出。 |
| 8.15 | _exit 与 return | 子进程执行失败时 _exit 立即结束，不经过普通 C++ 栈析构或 stdio 常规退出刷新；它确实是函数，是否允许是课程清单问题。 |
| 8.16 | waitpid + WNOHANG | 立即检查指定子进程；0 表示还没结束，PID 表示已获取状态，-1 表示错误。避免常规等待阻塞整个事件循环。 |
| 8.17 | 僵尸进程 | 子进程退出后仍需父进程 wait 回收状态；仅关管道不等于已经回收。 |
| 8.18 | 退出状态解码 | waitpid 写出的 status 不是直接的退出码；先 WIFEXITED，再 WEXITSTATUS。项目要求正常退出且码为 0。 |
| 8.19 | kill 与 SIGKILL | kill 发送信号；SIGKILL 强制终止，之后仍要 waitpid。当前 killChild 使用 waitpid(...,0)，可能短暂阻塞。 |
| 8.20 | SIGINT | 常由 Ctrl-C 产生；handleSignal 仅设 g_running=0，让主流程清理。 |
| 8.21 | SIGPIPE | 向读端已关闭的 pipe/socket 写入可能产生；忽略该信号后，代码可根据写操作返回值处理失败。 |
| 8.22 | sig_atomic_t / volatile / extern | sig_atomic_t 用于信号回调可安全访问的简单标量；volatile 要求保留相应访问语义；extern 声明 main.cpp 中的同一个变量。volatile 不是线程同步工具。 |
| 8.23 | 信号回调限制 | 不应在回调里随意用复杂 C++ 容器、流和 delete；当前只改简单标志，让正常流程退出。 |
| 8.24 | CGI 完成的两个条件 | 输出 EOF 与子进程退出是不同事件；可能先关闭 stdout 后继续运行，也可能退出时管道仍有未读数据。 |
| 8.25 | CGI Status | CGI 的 Status: 201 Created 要转换为 HTTP/1.1 201 Created 状态行；不能原样当普通头就假定客户端收到 201。 |
| 8.26 | 响应长度与连接管理 | 当前服务器完整拿到正文后重新算 Content-Length，并决定 Connection；CGI 只输出正文和相关响应信息。 |
| 8.27 | CGI 输出限制 | 128 MiB 限制的是该 CGI 累积输出（含 CGI 头），不是整个服务器内存，也不是输入限制。 |
| 8.28 | 流式 CGI | 一边读 CGI 输出一边发给客户端，配合有界缓冲与背压；当前没有实现，仍先收完整输出。 |
| 8.29 | 背压与双向死锁 | CGI 可能边读 stdin 边写 stdout；若服务器只顾写输入不读输出，两边有限管道都可能塞满。统一 poll 同时推进两个方向。 |

execve 的替换语义、参数、环境和解释器规则可对照 [Linux execve 手册](https://man7.org/linux/man-pages/man2/execve.2.html)。

| 12.12 | 后台与进程 | & 后台运行，$! 得后台 PID，wait 等结束，$? 看上一命令状态；PID 与客户端 fd 是不同编号体系。 |
| 12.13 | /proc 与 cgroup | /proc/PID/fd 用于观察进程 fd；memory.events 的 oom_kill 增量帮助定位 OOM。macOS 本机与 Linux 容器工具并不相同。 |
| 12.14 | Docker 网络 | 容器 loopback 不等于宿主机 loopback；宿主机访问通常需要发布端口并监听容器可达接口。 |
| 12.15 | Fedora 原生运行 | 目标是学校 Linux 上 make 后运行；macOS 静态分析不等于 Fedora 实测。解释器位置、测试二进制架构和权限仍需实机确认。 |
| 12.16 | 测试器的局限 | test_keepalive 第一条响应只 recv 一次，不是完整消息分帧器；test_partial_request 没有请求 close，可能等服务器空闲超时才结束。不要把测试脚本本身当协议标准。 |
| 12.17 | Git 与运行数据 | 代码、配置和文档适合提交；.build、二进制、会话数据和临时测试输出应按项目需要忽略。复习笔记记录快照，后续代码改变可能使行号过期。 |

## 15. 最后用五条真实路径串联复习

静态演示页面也涉及少量浏览器知识：

| 编号 | 知识点 | 简洁解释与代码联系 |
| --- | --- | --- |
| 15.01 | HTML 文档结构 | doctype 声明文档类型；html 包含 head 和 body；title 是页面标题，h1/h2 是内容标题，p 是段落。 |
| 15.02 | UTF-8 声明 | meta charset=UTF-8 指定 HTML 文本编码；网络正文仍按字节计数。 |
| 15.03 | 超链接 | a 的 href 指向 URL；autoindex 由服务器生成链接，点击后浏览器再发送 GET。 |
| 15.04 | 内联 SVG | assets/gallery.html 直接使用 svg、rect、circle、path、text 画图；图形嵌在 HTML 中，不需要独立图片请求。 |
| 15.05 | SVG 属性 | width/height 定尺寸，fill/stroke 定填充和描边；静态资源由浏览器渲染，C++ 只传字节。 |
| 15.06 | 可访问性 | gallery 的 role=img 和 aria-label 为图形提供语义和描述。 |
| 15.07 | 多资源请求 | 浏览器访问页面可能再请求图片、样式或 favicon；一次打开网页不一定只对应一个 HTTP 请求。 |
| 15.08 | 静态与动态内容 | 静态文件按原内容返回；autoindex 由 C++ 动态生成，Cookie/Session 页面由 CGI 动态生成。当前演示页面未包含 JavaScript 函数。 |

1. GET /：TCP → poll → recv → 状态机 → location / → 方法许可 → stat/ifstream → HTTP 序列化 → send → keep-alive。
2. multipart 上传：长度分帧 → boundary → MultipartPart → 文件名校验 → upload_store → write/close 检查 → 201/200。
3. CGI POST：body 完整 → 环境变量 → swap → pipe/fork/dup2/chdir/execve → poll 双向推进 → EOF + waitpid → 组装响应。
4. infinite.py：子进程无 I/O 活动 → 5 秒检查 → SIGKILL + waitpid → 500 → 关闭连接。
5. Session：Cookie 请求头 → HTTP_COOKIE → Python 校验 ID → 文件读取/增加次数 → Set-Cookie 或沿用 ID → CGI 响应发回。

每条都能说明“数据在哪个对象、当前在哪个阶段、下一步由谁触发、出错谁清理”，比只背函数名更接近真正掌握项目。
